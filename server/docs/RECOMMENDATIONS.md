# Система рекомендаций

[Бэкенд](BACKEND.md) · [API](API.md)

Подбор по содержанию: явные предпочтения пользователя + содержание понравившихся произведений + приоритет их типов. Модель только извлекает признаки из отзывов. Жанры, коэффициенты и баллы рассчитывает сервер без платных запросов.

## 1. Основания

| Данные | Использование |
|---|---|
| Отзыв или ручная отметка | Прямое отношение к тегу: +1, −1, смешанное 0 |
| Оценка 5 / 4 | Слабое положительное основание по содержанию: +0.3 / +0.2 |
| Оценка 1 / 2 | Слабое отрицательное основание: −0.3 / −0.2 |
| Оценка 3 | Не добавляет предположений по содержанию |
| Нет оценки, положительных отметок больше отрицательных | Слабое основание +0.15 |
| Нет оценки и отметок | Предпочтения не выводятся, даже при статусе «Завершено» |

Общая оценка учитывается и при наличии отзыва или ручного выбора. Например, отметка «уютная атмосфера» у понравившейся книги не отменяет остальные основания: её содержание, жанры и тип.

Предположения берутся из основных тегов каталога. Фоновый признак сам по себе не считается причиной высокой оценки. По тегу с явным ненулевым предпочтением оценочные вклады не добавляются. Отмеченные теги источника, включая смешанное отношение, также исключаются из его предположений.

Пока отзыв анализируется или анализ завершился ошибкой, предположения из этой записи не используются. После успешного анализа они учитываются вместе с найденными признаками.

У личной карточки нет разметки каталога. Используются её явные отметки, известные жанры и тип. Одно название предпочтений не задаёт.

## 2. Явные предпочтения

По каждому тегу складываются положительные и отрицательные отметки. Отрицательная сумма хранится без минуса.

```text
вес = (положительная сумма − отрицательная сумма)
      / (2 + положительная сумма + отрицательная сумма)
```

Вес находится между −1 и 1. Константа `2` ограничивает влияние одной отметки. Два плюса дают `0.5`; два плюса и один минус дают `0.2`.

`user_tags` хранит суммы по `library_tags`. При расчёте явного веса оценочные строки `source=rating` вычитаются: общие оценки обрабатываются отдельно и не дублируются.

## 3. Совпадения с кандидатом

Совпадение положительного предпочтения с основным тегом учитывается полностью, с фоновым: с множителем `0.25`. Отрицательное предпочтение учитывается полностью независимо от роли тега.

Редкие признаки различают произведения лучше общих. Их вес рассчитывается по каталогу:

```text
IDF = 1 + ln((число произведений с тегами + 1)
             / (число произведений с данным тегом + 1))
редкость = √IDF
вклад = вес × редкость / средняя редкость × роль тега
        / √(число основных тегов + 0.25² × число фоновых)
```

Средняя редкость взвешивается по абсолютным явным весам. Если весов нет, она равна `1`. Делитель уменьшает преимущество карточек с большим числом признаков.

Для положительной отметки учитывается жанр произведения, где она сделана:

```text
жанровый множитель = 0.5 + 0.5 × среднее сходство жанров источников с кандидатом
```

При полном совпадении множитель равен `1`, при несовпадении: `0.5`. Это ослабляет перенос одного общего признака между непохожими историями. Без известных жанров множитель равен `1`. Отрицательные отметки не ослабляются.

## 4. Содержание понравившихся произведений

Источник: запись библиотеки с основанием из первой таблицы. Сервер сравнивает его основные теги и жанры с кандидатом.

```text
сходство = сумма IDF² общих признаков
           / √(сумма IDF² признаков источника × сумма IDF² признаков кандидата)

вклад источника = основание × сходство тегов × сходство жанров
                  / (2 + сумма абсолютных оснований)
```

Каждая запись учитывается один раз. Для жанров IDF считается отдельно. Полное совпадение даёт `1`, отсутствие общих признаков: `0`. Неуказанные жанры не создают штрафа.

Вклад распределяется по общим основным тегам пропорционально `IDF²`. Доли тегов с явным отношением исключаются. Поэтому общая симпатия к книге не превращает прямо отмеченное «не понравилось» в плюс.

Пример: оценка 5, сходство тегов `0.5`, жанров `0.8`. До исключения явно отмеченных тегов вклад составляет `0.3 × 0.5 × 0.8 / 2.3 ≈ 0.052`.

Если у источника нет основных тегов, используются только известные общие жанры с дополнительным множителем `0.25`. Это позволяет учитывать оценку личной карточки, но не приравнивает один общий жанр к близкому содержанию.

## 5. Приоритет типа

Тип имеет отдельный коэффициент. Берутся только положительные основания из первой таблицы:

```text
коэффициент типа = 1 + 0.25 × сумма оснований этого типа
                       / (0.3 + сумма всех положительных оснований)
```

Одна книга с оценкой 5 даёт книгам коэффициент `1.125`; другим типам: `1`. При накоплении предпочтений одного типа коэффициент приближается к `1.25`. Если нравятся несколько типов, прибавка распределяется между ними.

Коэффициент увеличивает только положительную часть балла. Штрафы за нежелательные признаки сохраняются. Тип без совпадений по содержанию балл не создаёт. Другие форматы не исключаются; фиксированной квоты на них нет.

## 6. Выдача и обновление

```text
балл = положительные вклады × коэффициент типа + отрицательные вклады
```

При сортировке по соответствию выше больший балл. Это сравнительный балл, не вероятность.

- При положительных основаниях выдаются кандидаты с `score > 0`. После фильтров список может быть пустым.
- Без положительных оснований возвращается общая подборка; при сортировке по соответствию нежелательные признаки сдвигают карточки вниз.
- Библиотека при любом статусе и скрытые карточки исключаются до разбиения на страницы. Адаптация другого типа считается отдельным произведением.
- Объяснение указывает положительный признак или жанр и источник. Предположение по содержанию не выдаётся за слова пользователя.

Баллы сохраняются в `recommendations`. Пересчёт выполняется при изменении оснований, удалении записи, изменении типа или жанров личной карточки, обновлении разметки каталога. Просмотр страницы, фильтры и смена статуса без изменения впечатлений пересчёта не требуют.

Отдельные таблицы для жанровых и типовых предпочтений не нужны: исходные данные уже есть в библиотеке. Они вычисляются при обновлении сохранённых баллов.

## 7. Поиск похожих

«Найти похожее» сравнивает кандидатов с выбранным произведением, без личного профиля:

```text
сходство = число общих тегов / число уникальных тегов двух произведений
```

Для каталога берутся все теги, для личной карточки: положительные отметки. Без тегов сравниваются жанры. Источник, библиотека и скрытые карточки исключаются.

Коэффициенты заданы вручную и проверяются на демонстрационных сценариях. Обучения на пользовательских данных не было.
