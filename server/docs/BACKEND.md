# Работа бэкенда

[API](API.md) · [Рекомендации](RECOMMENDATIONS.md) · [Запуск](SETUP.md)

Python 3.12, FastAPI, SQLAlchemy, PostgreSQL 17. Миграции: Alembic. Запросы обрабатывает API `/api/v1`; анализ отзывов выполняет отдельный фоновый процесс, worker.

## 1. Вход

1. Пользователь отправляет email. Сервер сохраняет хеш одноразового кода в `codes` и отправляет код письмом через SMTP.
2. При подтверждении сервер проверяет код, создаёт аккаунт при первом входе и удаляет использованный код.
3. Браузер получает две HttpOnly-cookie: `access_token` на 15 минут и `refresh_token` на 30 дней.
4. После истечения access-токена фронт вызывает `POST /auth/refresh`. Сервер проверяет refresh-токен и выдаёт новый access. Срок refresh не продлевается.
5. Выход удаляет обе cookie. Токены в БД не хранятся; их сохранённые копии действуют до истечения срока.

Код действует 10 минут; допускается 5 неверных попыток. Повторная отправка доступна через 60 секунд. Каталог, библиотека и обложки доступны после входа.

## 2. Каталог и библиотека

Каталог загружается из `data/works.json` скриптом `data/load.py`. Он применяет миграции и обновляет карточки без дублей. Обложки хранятся отдельно в `app/covers/catalog`, в БД записан путь к файлу.

При добавлении произведения сервер создаёт запись `library`, связывающую пользователя с карточкой. В ней хранятся дата добавления, статус, оценка и личный отзыв. Одно произведение нельзя добавить одному пользователю повторно.

Если произведения нет в каталоге, сервер создаёт карточку `private_works` и запись библиотеки. Обязательны название и тип; остальные поля необязательны. Загруженная обложка преобразуется в WebP и сохраняется в `app/covers/private`. Личная карточка доступна только владельцу.

## 3. Отзыв и предпочтения

Для записи библиотеки доступны три варианта:

| Данные пользователя | Обработка |
|---|---|
| Отзыв: `liked`, `disliked`, `comment` | Модель определяет отношение к тегам |
| Ручной выбор тегов без отзыва | Сервер сохраняет выбранные отношения без вызова модели |
| Только оценка | Сервер учитывает основные теги оценённого произведения с меньшим весом |

Для личной карточки учитываются явные отметки, жанры и тип. Оценка без тегов даёт слабое основание через известные жанры.

Обработка текстового отзыва:

1. Сервер сохраняет текст и ставит его в очередь: `pending`.
2. Worker передаёт модели Qwen3.6 35B текст и допустимый список тегов. На время анализа статус меняется на `running`.
3. Модель возвращает теги, отношение к ним и фрагменты текста, подтверждающие результат. Сервер проверяет ответ и сохраняет признаки в `library_tags`.
4. По сохранённым признакам сервер обновляет предпочтения пользователя в `user_tags`, затем баллы рекомендаций. Статус анализа меняется на `done`.

Общие реакции вроде «имба», «кринж» или «вайб» без конкретного признака не создают теги. Если весь отзыв состоит из таких реакций, обращение к модели пропускается. В содержательном отзыве сленг учитывается вместе с контекстом; цитата сохраняется в исходном виде.

При ошибке анализа устанавливается `error`; повтор доступен через API. Если пользователь изменил отзыв до завершения анализа, ответ для старого текста не сохраняется. Для этой проверки используется `library.version`.

При редактировании отзыва прежние признаки перестают учитываться. После анализа их заменяют новые. При удалении записи её признаки также исключаются из предпочтений. Это предотвращает повторный учёт одного отзыва.

## 4. Рекомендации

При расчёте учитываются явные предпочтения, содержание и жанры понравившихся произведений. Тип имеет отдельный ограниченный коэффициент. Оценка продолжает учитываться при наличии отзыва или ручных отметок.

После изменения оснований сервер рассчитывает соответствие произведений пользователю и сохраняет баллы в `recommendations`. При открытии страницы используются эти баллы, повторный анализ отзывов не выполняется.

Перед выдачей сервер применяет фильтры и исключает произведения из библиотеки пользователя при любом статусе, а также скрытые карточки. Результаты сортируются выбранным способом; при сортировке по соответствию выше находится больший балл.

Если положительных предпочтений ещё нет, возвращается общая подборка. Для персональных рекомендаций сервер указывает признак или жанр, повлиявший на выбор, и произведение, из которого получено предпочтение. Расчёт: [RECOMMENDATIONS.md](RECOMMENDATIONS.md).

## Таблицы БД

| Таблица | Данные и связи |
|---|---|
| `users` | Аккаунты: email, имя, роль, дата создания. Владелец записей библиотеки, личных карточек и предпочтений |
| `codes` | Код входа для email: хеш, число неверных попыток, время создания и истечения. На email хранится один код |
| `types` | Справочник типов произведений. Используется в `works` и `private_works` через `type_id` |
| `genres` | Справочник жанров общего каталога и личных карточек |
| `tags` | Фиксированный справочник признаков для разметки каталога, анализа отзывов и ручного выбора |
| `work_groups` | Группы адаптаций одной истории. Связь с произведениями через `works.group_id` |
| `works` | Общий каталог: название, тип, описание, создатели, год, страна, возрастная маркировка, ключ обложки и группа адаптаций |
| `private_works` | Личные карточки с полями произведения и владельцем `user_id`. В общий каталог и группы адаптаций не входят |
| `work_genres` | Связь произведений каталога с жанрами: `work_id`, `genre_id` |
| `private_genres` | Связь личных карточек с жанрами: `private_id`, `genre_id` |
| `work_tags` | Связь произведений каталога с тегами: `work_id`, `tag_id`. `is_main` определяет основной или фоновый признак |
| `library` | Запись пользователя о произведении: ссылка на общую или личную карточку, дата добавления, статус, оценка, `liked`, `disliked`, `comment`, статус анализа и версия отзыва |
| `library_tags` | Вклад записи библиотеки по тегу: `value`, источник `review` / `manual` / `rating`, цитата для анализа отзыва. Допускаются любые теги справочника |
| `user_tags` | Суммы положительных и отрицательных вкладов пользователя по тегу. `weight` вычисляется БД: `(positive − negative) / (2 + positive + negative)` |
| `recommendations` | Сохранённый `score` для пары пользователь + произведение каталога. Используется для персонального ранжирования |
| `hidden` | Пары пользователь + произведение каталога, исключённые пользователем из рекомендаций и поиска похожих |

В `library` указано либо `work_id`, либо `private_id`. Оценки и отзывы принадлежат записи библиотеки; у карточек каталога общего рейтинга нет. `author` хранит создателей одной строкой, подпись поля определяет фронт. Адаптации имеют общую группу, но отдельные карточки, оценки и отзывы.
